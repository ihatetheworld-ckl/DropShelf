# 测试与手动验收

## 自动检查

```bash
swift test
./scripts/test_cross_volume.sh
./scripts/package_release.sh
```

`swift test` 在没有第二个测试卷时会跳过真实跨卷测试。`test_cross_volume.sh` 创建专用 APFS 镜像后运行完整套件，结束时卸载清理。所有移动、冲突和删除验证均使用专门生成的测试文件。

v1.0.1 发布准备在 Apple Silicon、macOS 27.2、Xcode 27.2 / Swift 6.4.2 环境验证 34 项测试：

- 文件移动：相同路径、目录别名、同名冲突、保留两份、失败恢复、禁止移入自身、临时资源复制、真实跨卷复制。
- ZIP：真实解包核对同名文件、文件夹和隐藏文件，复制失败、并发任务隔离。
- 临时文件：最后引用释放、跨架子共享、剪贴板保留、重启导出保留、孤立资源清理、活跃会话锁及用户文件保护。
- 架子：批量折叠三种状态、异步导入快照、新增项目保留、任务失败、重复关闭、固定、超时折叠及任务期间禁止退出。
- AppKit：真实窗口堆叠/网格/折叠渲染，Quick Look 打开、内容快照、关闭及数据源释放。

`verify_release.py` 校验 SHA-256、源码提交记录、ZIP 与只读 DMG 中的应用内容一致性、应用版本、构建号、签名、图标和两种架构的 macOS 13.0 部署目标。脚本失败时不得将附件作为验证通过的发行包。

CI 运行同一套测试和打包脚本。CI 运行的 macOS 版本、架构及工具链以对应 Actions 日志为准。Intel 或旧版系统的真机体验，需要单独记录。

## v1.0.2：拖拽门控与触觉反馈

v1.0.2 发行准备于 2026-11-08 在 Apple Silicon、macOS 27.2 上运行完整套件：52 项通过、0 失败，包含专用 APFS 跨卷测试。Universal 构建的两种架构、macOS 13.0 部署目标及 ad-hoc 签名也已检查；这不代表物理三指手势或震动手感已通过验收。

新增回归覆盖无按下事件、旧文件拖拽数据残留、鼠标抬起/新手势、实际私有剪贴板代际、受支持类型、内部拖出、Option、冷却时间、内容变化和每次拖拽一次唤起；架子集成测试通过注入反馈回调检查新建/复用、固定架子及反馈开关。测试不据此宣称已经感受到触控板震动。

手动验收使用专用测试文件：

1. 不拿文件，在桌面空白处三指来回移动，以及拖动窗口或选择区域，不应唤起。先完成一次文件拖放，再重复空白晃动，检查残留数据不再误触发。
2. 从 Finder 开始三指拖动测试文件，来回晃动，应唤起一次；持续晃动不重复提示。取消后松开，再进行空白三指晃动，不应唤起。Option 入口执行同样检查。
3. 手指接触支持 Force Touch 的触控板时，新建或复用架子应尝试一次短触觉提示；关闭“唤起架子时提供触觉反馈”后不再提示，音效开关与触觉开关互不影响。系统可能因设备、设置或未接触触控板而省略反馈。

已在本机正常退出旧版并启动修复试用版，核对了运行路径及两个全局快捷键注册成功；这不作为物理手势与震动效果通过的证据。

检测仅在观察到本次按下之后的拖拽数据变化时启用；应用在拖拽中途启动时，请重新开始拖拽。它不会为确认拖拽而读取文件内容或使用私有系统接口。

## 开发中：双次触觉提示

2026-11-12 在 Apple Silicon、macOS 27.2 / Swift 6.4.2 上运行完整 71 项回归，0 失败、0 跳过；新增 8 项调度回归。Universal 的 arm64/x86_64、macOS 13.0 目标及 ad-hoc 签名通过构建检查。

经用户确认当前架子无待处理内容后，已正常退出旧试用版并启动双次触觉试用版，核对实际运行路径；新双次提示的主观手感等待用户比较反馈。

用户反馈原有单次提示可以感知，但希望更明显。当前开发分支使用两次 `.generic` / `.now` 请求，间隔约 120 毫秒，保留单次选项及“试震”按钮。Apple 的[公开反馈方法](https://developer.apple.com/documentation/appkit/nshapticfeedbackperformer/perform(_:performancetime:))不提供振幅参数或执行成功回执；系统可省略反馈，手指不接触 Force Touch 触控板时不执行。按[官方模式语义](https://developer.apple.com/documentation/appkit/nshapticfeedbackmanager/feedbackpattern)，架子唤起使用通用提示，不把对齐或压力级别模式当作“更强档位”。

`ShelfHapticFeedbackTests` 注入底层请求及调度器，验证单次/双次、关闭后重开、样式往返切换、新请求覆盖、显式取消、释放及设置持久化；另用真实主队列调度和注入请求验证第二次异步执行。它们不测量触控板振幅，也不证明硬件实际执行了两次。

手动验收：

1. 使用支持 Force Touch 的触控板，保持手指接触，打开“唤起架子时提供触觉反馈”，在单次、双次模式下点击“试震”比较。使用鼠标点击后若未接触触控板，系统可能不反馈。
2. 拖起专用测试文件，晃动或按 Option 唤起架子，检查双次提示是否比原单次更容易辨识，且不干扰拖放。新建和复用空白架子都需检查。
3. 关闭触觉开关后唤起和试震不应再请求反馈；在两次之间关闭开关或切换为单次，旧的第二次请求应取消。
4. 关闭音效后重复检查，确认不是把提示音当作触控板反馈。记录是否能分辨两次触感；未取得用户试用反馈前，双次手感保持“未验收”。

## 手动验收

### v1.0.3：Finder 拖出行为

2026-11-12 在 Apple Silicon、macOS 27.2 / Swift 6.4.2 上运行完整套件：63 项通过、0 失败、0 跳过，包含专用 APFS 跨卷测试；其中新增拖出回归 11 项。Universal 的 arm64/x86_64 构建及 ad-hoc 签名通过。这些检查不代表已实测 Finder 的拖放选择、修饰键或跨卷移动。

经用户确认旧版无待处理内容后，已正常退出旧版并启动本次试用构建，核对了实际运行路径。Finder、浏览器及修饰键的端到端拖放仍待以下手动验收。

`DragOutTests` 使用真实 AppKit 拖拽源方法、`NSDraggingItem`、私有剪贴板和独立测试文件，检查原始文件/文件夹的复制移动掩码与 URL 数据、不提供链接/删除/自定义操作、设置持久化与手势快照、混合临时批次复制及跨架子读取、取消与重复结束、部分移动、断开目标的符号链接和失败路径保留。测试中的 `NSDraggingSession` 用作回调参数，没有实际驱动 Finder，不代表下列交互已通过。

使用专用源目录 A、目标目录 B，以及可丢弃的第二卷 C，每个用例重新创建测试文件，勿使用日常文件：

1. A 中创建文件及含子文件的文件夹，拖入架子后普通拖到同卷 B。应为真实移动，B 内容完整，A 对应项消失；Finder“显示简介”的种类不得为替身。
2. 重新建测试文件，按住 Option 拖到 B，指针应有“＋”，A、B 内容均完整；按住 Command 拖到 C 应移动。不按键拖到 C 应复制。分别测试单文件、文件夹和多选。
3. 开启“拖出时始终复制”，普通及按 Command 拖出均保留源文件；关闭后恢复默认。普通拖出不得生成替身；默认模式下 Option+Command 的替身组合应被拒绝。
4. 用 Escape 取消，或在 Finder 同名冲突中取消/跳过，核对原文件不受损；仍在原路径的移动项保留。Finder 若异步完成，架子可能保留旧路径；复制被接收后的逐项失败不由 AppKit 回调报告，应回原目录核对后重新导入。
5. 关闭“拖出后自动移除”后复制应保留架子；已确认移走的源路径应移除。拖拽期间新增项目及未选中项不得丢失。
6. 将生成的文本、图片、链接或 ZIP 同时放在两个架子及剪贴板中，拖出一个架子、关闭源架子后，另一个架子和剪贴板仍可读取；与普通文件混合拖出时整批复制。

### 其他场景

以下场景不能仅凭源码、内部回调测试或快捷键注册成功判为通过。前次原生自动化连接超时，未取得可靠的 Finder/浏览器端到端证据；本机只有一个内置显示器。

1. **导入**：从 Finder 拖入文件、文件夹；从浏览器分别拖入图片、选中文字和链接，核对内容与数量。
2. **唤起**：外部拖拽时晃动鼠标、按 Option、拖到菜单栏；使用 `⇧⌘D` 新建，用 `⌥⇧Space` 分别检查全部展开、全部折叠和混合状态。
3. **拖出**：把单文件和多选项目拖到测试目录，比较文件内容；用 Escape 取消，确认项目保留；跨架子拖放后关闭源架子，确认目标仍可读取。
4. **外部生命周期**：复制生成内容后关闭全部架子，超过 30 秒后在 Finder 粘贴；重启应用后再次确认。Quick Look 打开时移除或关闭源架子，检查无异常。
5. **架子状态**：固定与取消固定、清空、自动关闭、空白超时折叠；打包期间新增内容，核对未选中项和新增项保留；只用测试文件验证同名和原位移动。
6. **显示环境**：多屏边缘唤起、移动、折叠与展开；切换桌面及全屏应用，检查位置、焦点和可见性。

这些手势、跨应用、全屏、多屏以及 Intel/macOS 13 真机测试在取得实际证据前保持“未验收”。
