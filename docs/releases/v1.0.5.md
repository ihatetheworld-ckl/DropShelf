## DropShelf v1.0.5 — 重复实例与旧版误触发修复

本版本增加启动阶段的重复实例保护，避免多个 DropShelf 副本同时监听鼠标和注册快捷键，造成误唤起与触觉表现不一致。

### 问题与修复

- 本机排查发现 `/Applications` 中的 v1.0.0 与本地 v1.0.4 同时运行。旧版仍会将拖拽剪贴板残留类型用于晃动判断，且没有通用双次触觉功能。
- 正常退出两个实例、只运行一个 v1.0.4 后，用户复测空白三指移动、窗口/文字选择，以及拖放结束后的移动，确认“不再误触发，触觉也恢复了”。
- 新版启动前检查已有实例。同版本重复启动时激活原进程并退出新副本，保留原有架子状态，不开启第二套监听器。
- 发现其他版本已运行时，显示具体版本和路径，提示先处理架子内容并退出已有版本；不会强制终止已有进程。
- 保留当前拖拽门控和通用双次 240 毫秒触觉方案。触觉开关、单次/双次选项及“试震”仍可在偏好设置调整。

### 验证范围

本地在 Apple Silicon、macOS 27.2.1 / Swift 6.4.2 上通过 78 项回归测试（0 失败、0 跳过），含新增 7 项启动策略回归，以及原有拖拽、触觉、文件安全、专用 APFS 跨卷、ZIP、缓存和架子状态测试。

已使用 NSWorkspace 真正启动第二个应用进程，观察到新 PID 随后退出，原 PID 保留，最终仅一个实例。不同版本的提示窗口尚未做交互自动化验收。Universal 的 arm64/x86_64、macOS 13.0 目标及 ad-hoc 签名通过构建检查；Intel/macOS 13 真机、其他触控板、多屏和全屏仍需单独验收。

### 下载与升级

版本 **1.0.5 / build 6**，最低部署目标 **macOS 13.0**。提供 Universal 2 DMG、ZIP、`SHA256SUMS.txt` 和包含源码提交的 `release-manifest.json`。

升级前处理所有旧架子的内容并退出已有版本，再更新日常使用的 `/Applications/DropShelf.app` 或其他安装入口。旧版程序自身没有新启动保护；仅在开发目录运行新版，同时保留旧的日常启动入口，仍可能重新启动旧版。

安装包采用 ad-hoc 本地签名，未经过 Apple 公证。请核对来源与校验和，按 macOS 系统提示处理首次打开。详细手动验收范围见仓库测试文档。
